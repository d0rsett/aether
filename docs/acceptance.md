# Приёмка этапа 1

Не считать весь MVP принятым до проверки native Development и Release на Windows.

## Ручной сценарий

1. `npm run tauri dev`: открывается desktop-окно без обязательной сети.
2. Создать тестовую папку через системный диалог и выбрать её как vault.
3. Создать папку `Заметки`, в ней `Привет.md`; открыть файл и ввести Markdown.
4. Нажать Ctrl+S; проверить реальный файл сторонним редактором.
5. Открыть второй файл, переключать вкладки, проверить undo/redo, Ctrl+F и Ctrl+H.
6. Переименовать сохранённую заметку; существующая цель должна вызывать ошибку.
7. Изменить открытый файл сторонним редактором, затем попробовать сохранить старый буфер. Получить конфликт; содержимое сторонней версии должно сохраниться. Сохранить свою версию как копию.
8. Удалить чистую заметку. Убедиться, что её содержимое есть в `.aether/trash`.
9. Переключить тему, закрыть/открыть приложение. Последний vault, тема и вкладки восстанавливаются.
10. Внести изменения, подождать 1 секунду и закрыть приложение с подтверждением. При повторном запуске восстановится черновик; исходный `.md` до Ctrl+S не изменится.
11. Проверить недоступную папку/readonly-файл и закрытие несохранённой вкладки: понятная ошибка/предупреждение без падения.
12. Собрать `npm run tauri build -- --no-bundle`, повторить основные действия в Release `.exe`.

## Автоматизация

- Rust unit-тесты: временное настоящее хранилище, Unicode CRUD, >1 МБ, конфликт сохранения/rename/delete, существующий destination, недопустимые пути, settings roundtrip.
- Frontend: модель вкладок, recovery isolation, интеграционные сценарии с mock IPC.
- Native E2E настроен через официальный Playwright/WebView2 CDP в отдельной сборке. Он проверяет настоящие файлы и IPC, не mock runtime. Ручная проверка OS drag/Windows Snap остаётся отдельной от функциональной приёмки.

Среда: Node 24.13.1, Rust/Cargo 1.93.1, Windows x64. `tauri info` обнаружил WebView2 и сообщил: `Couldn't detect any Visual Studio or VS Build Tools instance with MSVC and SDK components`. В Visual Studio 2026 есть отдельные binaries linker, но нет полного набора C++ libraries и Windows SDK; просто добавить каталог linker в PATH недостаточно.

Первоначальный доступ Cargo к registry завершался DNS-ошибкой в sandbox, затем тайм-аутами на больших ответах. Версии зависимостей зафиксированы в lock-файлах; зависимости ядра загружены через локальный совместимый транспорт к официальному crates.io. Все Rust-тесты ещё требуется выполнить после установки полного toolchain. Этап 1 **не прошёл полную приёмку**; следующие этапы не начаты.

Есть предупреждение Vite о lazy chunk редактора ~551 КБ до gzip (~191 КБ gzip). Основной стартовый chunk ~260 КБ до gzip (~81 КБ gzip); редактор загружается при открытии заметки. Это размеры артефактов, не измерения времени старта или RAM.

Основная часть этапа 2 реализована: pulldown-cmark, wiki resolution, YAML, теги, backlinks/исходящие ссылки, SQLite FTS5 с Unicode61, фильтры и фоновый notify watcher. Дополнительно повреждает собственный SQLite-кеш, перезапускает приложение и подтверждает, что Markdown по-прежнему открывается и сохраняется.

## Сложные блоки внутри Live Preview

Добавлены StateField с block/inline widgets для таблиц, изображений, формул и Mermaid. Используется тот же Rust renderer и React renderer чтения. Источник не переписывается; курсор/выделение и кнопка «Изменить» возвращают Markdown. Нет разбора на каждый keystroke: применяется debounce 160 мс, прежние незатронутые диапазоны сдвигаются через ChangeDesc. Ответ для устаревшего Text snapshot игнорируется. Скрытые вкладки не запрашивают preview, React roots/observers освобождаются при снятии widgets. Контракт: `docs/live-blocks.md`.

Native проверка выявила неправильную геометрию клавиатурного перехода после раскрытия widget: внешние vertical margin не входят в измеряемую высоту. Внешние отступы убраны; исходные пустые строки и внутренние отступы сохраняют оформление. После исправления исходный сценарий ввода непосредственно с кнопки редактирования проходит без дополнительного щелчка по строке. В ожидаемом тексте теста используется replacement callback, чтобы JavaScript не превращал `$$` в один `$`.

## Переименование и корзина папок

В контекст папки добавлены «Переименовать» и «Переместить в корзину». Непустая папка переименовывается в строке дерева вместе с её содержимым, с обновлением открытых путей и wiki-/Markdown-ссылок. Общий журнал расширен признаком directory и описью папки с хешами файлов; старые журналы заметок читаются прежним способом. Перед применением и отменой проверяется состав папки и внешние изменения. Ошибка записи ссылок откатывает директорию и предыдущие Markdown-версии; при невозможности безопасного отката сохраняется pending-журнал для восстановления. Активные вкладки и выбранная папка синхронизируются, Undo работает для всей операции.

Удаление требует подтверждения и перемещает всю папку в уникальный .aether/trash/folder-*/<имя>, включая бинарные файлы и заметки с невалидным UTF-8. Черновики внутри папки сохраняются с проверкой ревизии, вложенные вкладки закрываются, остальные остаются. Содержимое не удаляется рекурсивно; нельзя удалить корень, служебные пути или папку при незавершённой операции.
