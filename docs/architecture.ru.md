# Архитектура

[English](architecture.md) · [README](../README.ru.md)

## Слои

React управляет reducer рабочей области, вкладками, сессиями, черновиками и интерфейсом. CodeMirror 6 отвечает за редактирование исходника и decorations/widgets Live Preview. Режим чтения отображает текущий буфер. `src/services/api.ts` — типизированная граница IPC; произвольного filesystem/shell API у frontend нет.

Команды Tauri в `src-tauri/src/lib.rs` проверяют активное хранилище, запускают блокирующую работу вне UI, показывают системные диалоги, управляют индексом/watcher и отправляют `knowledge:changed`. Независимый crate `aether-core` не зависит от Tauri: пути, файлы, настройки, Markdown, ссылки, вложения, индексирование, watcher и транзакции переименования находятся в нём. У него отдельные Cargo workspace и lockfile.

## Источники истины

Исходные Markdown-файлы являются источником истины. SQLite FTS5 — удаляемый индекс вне хранилища. Watcher обновляет затронутые записи и дерево. Открытые буферы не заменяются внешними изменениями автоматически. Связи справа описывают сохранённую версию, а свойства — текущий буфер; переходы к якорям могут разбирать текущий буфер.

Вкладка содержит текущий текст, сохранённый текст и ревизию. Сохранение использует снимок: его подтверждение не должно стирать ввод, сделанный во время запроса. Сохраняются BOM и тип перевода строки. Ревизии обнаруживают завершённые внешние изменения, но не являются межпроцессной блокировкой.

## Транзакции и корзина

Запись использует временные файлы и проверку ревизии; создание не перезаписывает существующую цель. Переименование/перенос строит план по реальным файлам, обновляет поддерживаемые wiki-/Markdown-ссылки, изображения и reference definitions, проверяет снимки и перед применением сохраняет журнал/копии в `.aether/`. Обычный UI применяет сразу; отдельная команда предпросмотра использует ту же границу планирования. Backend принимает токен операции, а не произвольный клиентский план замены.

Транзакция папки хранит опись дерева/хеши, включает вложения и пустые каталоги, обновляет пути заметок/вкладок и поддерживает Undo/восстановление. Восстановление проверяет текущие пути/содержимое перед записью. При конфликте журнал сохраняется для явного восстановления вместо перезаписи посторонних изменений. Старые журналы заметок остаются читаемыми.

Корзина отделена от Undo переименования. После подтверждения содержимое сохраняется в `.aether/trash/`; папка перемещается целиком. Восстановление ручное. Приложение не использует корзину ОС для этой операции.

## Граница отображения

Панель свойств разбирает текущий буфер моделью YAML-документа без раскрытия YAML-ссылок. Простые поля верхнего уровня меняются по исходным диапазонам; flow mappings сериализуются внутри шапки. Сложные конструкции остаются под контролем исходного режима. Команды свойств содержат ожидаемую шапку и применяются к текущему документу CodeMirror отдельными транзакциями истории, сохраняя промежуточные правки тела и отображённое выделение. Файловые API и настройки типов Obsidian не изменяются.

Rust преобразует Markdown в инертную модель отображения. Raw HTML заметки остаётся текстом. Source и Live Preview используют один CodeMirror state, сохраняя историю. Inline-синтаксис раскрывается у активного фрагмента; rich-блоки показывают исходник при выделении/редактировании. После ввода разбор откладывается; устаревшие widgets убираются/сдвигаются, а не применяются к посторонним позициям.

Встраивания заметок используют общий механизм разрешения ссылок. Rust выбирает разделы/блоки по диапазонам навигации после разбора всего документа, сохраняя reference definitions. `NotePreviews` передаёт текущие открытые буферы и ревизии индекса в чтение и независимые React-корни Live Preview; встроенное содержимое не записывает файлы и не редактирует содержащий его буфер. Вложенные контексты сохраняют исходную заметку для разрешения ссылок/вложений. Загрузка отменяется при смене контекста/буфера; цепочки разрешённых путей/якорей и лимиты глубины/количества ограничивают рекурсию. Флажки встроенных задач доступны только для чтения; для правок открывается оригинал.

Вложения ограничены активным хранилищем, поддерживаемыми растровыми форматами и размером 8 МиБ. Mermaid отображается в iframe без scripts, same-origin и доступа к сети. KaTeX ограничивает недоверенный ввод. CSP и точечные Tauri capabilities ограничивают frontend; открытие HTTP(S) — отдельная явная native-команда.

## Хранение и совместимость

Псевдонимы YAML хранятся в отдельной индексированной таблице удаляемого кеша. Версия схемы 2 перестраивает старые записи без изменения Markdown. Общий механизм разрешения ссылок проверяет реальные пути/имена перед псевдонимами; подсказки возвращают настоящий путь и необязательный псевдоним, чтобы вставлять wiki-ссылки с фактическим назначением и подписью. Обновление индекса пересчитывает назначения при изменении или удалении псевдонимов. Планирование переименования заполняет псевдонимы из реальных файлов в каталогах до/после операции, сохраняя ссылки и исправляя перекрытие новым именем файла независимо от индекса приложения.

`settings.json` хранит последнее/недавние хранилища в app-data Tauri; рядом находятся индексы. WebView хранит UI, сессии и черновики. Резервирование происходит примерно через 700 мс после ввода и сразу при штатном закрытии/переключении; ошибки хранения показываются пользователю. Восстановление черновика не записывает исходный файл автоматически.

Переименование в Aether меняет продукт, заголовок, пакет и бинарник. Identifier `app.aether.notes`, метаданные `.aether/` и ключи сессий намеренно сохранены. Native-тесты используют отдельный identifier, явный data-directory override и профиль WebView; обычная сборка не включает эту возможность переопределения.

## Ограничения и проверки

Межпроцессная блокировка, полная защита от намеренных файловых гонок, plugin runtime, шифрование, синхронизация и автоматическое обновление не реализованы. Поддерживаемые операции отклоняют symlink/reparse пути, но проверки не заявляют descriptor-relative TOCTOU-защиту. Надёжность записи зависит также от ОС/накопителя; черновики не заменяют резервные копии.

Vitest проверяет модель, редактор, компоненты и orchestration с mock IPC. Rust-тесты используют настоящие временные файлы для ревизий, traversal, ссылок, транзакций, восстановления и корзины. Windows native E2E работает с настоящим IPC Tauri через изолированный скрытый WebView2/CDP; это не бенчмарк производительности или native-перетаскивания окна. Обычная release-сборка собирается отдельно без тестовой feature.

Ранние инженерные записи из README являются историческими и могут содержать ограничения прежних этапов.
