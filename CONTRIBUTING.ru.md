# Участие в разработке

[English](CONTRIBUTING.md) · [README](README.ru.md)

## Подготовка

Установите [инструменты разработки](README.ru.md#запуск-и-сборка), затем выполните `npm ci` и `npm run tauri -- dev`. Используйте отдельные тестовые хранилища. Личные данные держите вне исходников или в игнорируемой папке `vaults/`.

Перед существенными изменениями прочитайте [архитектуру](docs/architecture.ru.md) и инструкции репозитория. Правила файлов, путей и индекса находятся в `aether-core`, интеграция с рабочим столом — в `src-tauri/src`, типизированный IPC — в `src/services/api.ts`, состояние рабочего пространства — в `src/app` и `src/workspace`, расширения редактора — в `src/editor`, режим чтения — в `src/reading`.

## Сохраняйте надёжность письма

Текущий буфер редактора определяет несохранённый текст. Используйте транзакции CodeMirror с отображением позиций; сохраняйте выделение, отмену, фокус и прокрутку. Отбрасывайте устаревшие асинхронные ответы при смене заметки/хранилища. Не сохраняйте Markdown автоматически. Сохраняйте проверки ревизий, восстановление конфликтов, ограничения путей и переносимость хранилищ.

Используйте общие темы, иконки, меню и диалоги. Английские и русские строки интерфейса добавляйте через `src/i18n`; пользовательский текст не переводите. Переводите также подписи доступности и ошибки. Обновляйте обе версии документации вместе; снимайте настоящий локализованный интерфейс, не подменяйте надписи на картинках.

## Проверки

```powershell
npm test
npm run build
npm run format:check
npm run repo:check
cargo fmt --manifest-path src-tauri/Cargo.toml --all -- --check
cargo fmt --manifest-path src-tauri/crates/aether-core/Cargo.toml -- --check
cargo test --locked --manifest-path src-tauri/crates/aether-core/Cargo.toml
cargo clippy --locked --manifest-path src-tauri/Cargo.toml --all-targets --all-features -- -D warnings
```

Для интеграции с рабочим столом запускайте подходящие [нативные сценарии](docs/native-testing.ru.md), для визуальных правок осматривайте интерфейс. У ядра отдельные manifest и lock-файл. Сохраняйте оба Cargo lock-файла и `package-lock.json`. CI работает на Windows и собирает обычное приложение, но не заменяет локальные проверки взаимодействия.

Для форматирования frontend, документации и скриптов используйте `npm run format`, для Rust — Cargo fmt. Добавляйте содержательные регрессионные тесты поведения, а не проверки, повторяющие косметическую реализацию.

## Ревью и публикация

Опишите результат для пользователя, реально выполненные проверки и ограничения. Просмотрите полный diff и подготовленные к коммиту файлы; включайте только относящиеся к задаче изменения. Не публикуйте хранилища, профили, кеши, базы, сборки, секреты и личные пути. `npm run repo:check` помогает с гигиеной репозитория, но не заменяет ревью.

Перед разрешённым коммитом/пушем проверьте ветку, upstream и remote. Не переписывайте общую историю и не применяйте force-push без явного разрешения. Сообщения коммитов пишите по-английски: заголовок с глаголом действия, краткий контекст, список значимых изменений и фактическая проверка/ограничения.

## Сборки и релизы

Обычную версию собирайте без функции `e2e`. Не закрывайте пользовательское приложение ради замены занятого файла; используйте другую папку сборки Cargo. Установщики и программы публикуйте вложениями релиза, указывая требования Windows/WebView2, подпись и контрольные суммы. Не коммитьте сборки. Подписание, автопубликация и автообновление не настроены; лицензия проекта не выбрана.

## Необязательный транспорт Cargo

Обычно сборка использует crates.io. Если большие ответы реестра не проходят, `node scripts/cargo-registry-proxy.mjs` предоставляет необязательный локальный транспорт с кешем в игнорируемой `.build-cache/registry`. Cargo продолжает проверять контрольные суммы; глобальные настройки не меняются.

Для нативной тестовой сборки с заполненным кешем:

```powershell
$env:AETHER_CARGO_PROXY = '1'
npm run build:e2e
Remove-Item Env:AETHER_CARGO_PROXY
```

Этот режим использует Cargo без сети и не заменяет требования Windows SDK/MSVC.
