# Участие и публикация

[English](CONTRIBUTING.md) · [Документация проекта](README.ru.md)

## Разработка

Установите инструменты из README, выполните `npm ci` и `npm run tauri -- dev`. Для файловых операций, ссылок, конфликтов и восстановления нужны содержательные тесты. Не используйте личное хранилище для проверок. Не добавляйте в Git кеши, настройки приложения, заметки пользователя, ключи и собранные программы.

Перед PR выполните проверки из README. Для изменений native/UI-интеграции запускайте native E2E на Windows. Обновляйте обе языковые версии README. Независимый crate `aether-core` исключён из Cargo workspace host-приложения: его тесты/форматирование запускаются отдельно. Сохраняйте оба Cargo lockfile и `package-lock.json`.

`npm run format` форматирует frontend, документацию и скрипты; Rust форматируется Cargo fmt. Windows CI проверяет обычную release-сборку; native-тесты запускаются локально. В PR опишите поведение для пользователя, проверки и ограничения. Не публикуйте логи с личными путями и текстом заметок.

## Первая загрузка на GitHub

Локальная ветка — `main`. URL репозитория и учётные данные не зашиты. Создайте пустой репозиторий на GitHub без генерации README/лицензии. В корне проекта:

```powershell
npm run repo:check
git status --short --untracked-files=all
git add .
git diff --cached --stat
git diff --cached --check
npm run repo:check
git commit -m "Initial Aether source"
```

Если Git попросит, настройте имя/email автора. Подставьте URL **своего** репозитория:

```powershell
git remote add origin <YOUR_GITHUB_REPOSITORY_URL>
git push -u origin main
```

Замените плейсхолдер с угловыми скобками перед выполнением. Если `origin` уже есть, сначала проверьте `git remote -v`. Просмотрите содержимое staged diff, а не только имена. Аудит проверяет tracked и неигнорируемые untracked файлы, находит tracked-файлы под ignore, распространённые форматы ключей/личные home-пути, файлы больше 10 МиБ и проверяет правила исключений. Шаблоны не гарантируют обнаружение любого секрета. Не обходите исключения через `git add -f` для личных данных.

В исходники включены код, lockfile, иконки, документация, тесты и отобранные снимки синтетических тестовых хранилищ. Исключены `target/`, `dist/`, зависимости, тестовые профили/хранилища/отчёты, runtime `.aether/`, локальные настройки/базы, env-файлы, ключи и бинарники. `.env.example` допустим только с безопасными плейсхолдерами. Исключение `.aether/` не скрывает произвольные папки с личными заметками: храните реальные хранилища вне исходников или в игнорируемой корневой папке `vaults/`.

При подготовке не создаются первый коммит, remote и push. Лицензия проекта не выбрана; выберите её осознанно до позиционирования проекта как open source.

## Релизы

Собирайте обычную версию без feature `e2e` командами из README. Проверяйте на отдельном тестовом хранилище. Размещайте `aether.exe`/NSIS в GitHub Releases, а не среди исходников. Укажите версию, требования Windows/WebView2, наличие подписи и SHA-256. Не распространяйте профили разработки, локальные настройки, `.aether/` и тестовые заметки. Автопубликация и подпись не настроены.

## Необязательный обход проблем Cargo

Обычная сборка использует crates.io напрямую. `scripts/cargo-registry-proxy.mjs` нужен только при проблемах с большими registry-ответами: выдаёт официальные данные crates.io/index через loopback, кеширует в `.build-cache/registry`. Cargo проверяет checksums; глобальные настройки не меняются.

В отдельном терминале:

```powershell
node scripts/cargo-registry-proxy.mjs
```

Для одной команды разработки:

```powershell
npm run tauri -- dev -- --config 'source.crates-io.replace-with="aether-local"' --config 'source.aether-local.registry="sparse+http://127.0.0.1:1421/"'
```

Для native-сборки с уже заполненным registry-кешем:

```powershell
$env:AETHER_CARGO_PROXY = '1'
npm run build:e2e
Remove-Item Env:AETHER_CARGO_PROXY
```

В этом режиме helper запускает Cargo офлайн. После работы остановите proxy через Ctrl+C. Это только транспортный обход; компоненты MSVC/SDK всё равно нужны.
